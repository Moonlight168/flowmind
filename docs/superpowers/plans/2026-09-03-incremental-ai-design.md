# AI 增量设计、双层校验与安全预览实施计划

> 状态：已完成（2026-09-03）

## 验证结果

- AI 服务 Ruff 检查通过，后端 179 条单元/集成测试全部通过，覆盖前置基线处理、增量操作、角色/分类校验、BPMN 元数据合并、SSE 与会话隔离。
- 前端生产构建通过；VForm3 依赖的既有 eval 和大分包告警不影响构建。
- 双轴代码审查发现的全量替换授权、候选预览隔离、表单引用和嵌套字段校验问题已修正。
- 所有设计请求及黄金集实验均携带 trace/session 元数据进入 Langfuse，结果包含稳定状态、校验和操作信息。

## 本轮收口

- 设计图统一为 `prepare → design → review → format`：前置节点负责请求类型/模式校验和分类、BPMN、VForm3 基线标准化，SSE 与 Langfuse 可直接观察该阶段。
- 设计链就绪探针同时检查降级开关、额外 Provider 尝试预算和结构化 Provider 数量；本地与生产 Compose 只有满足真实结构化降级条件才把实例标记为健康。
- BPMN 增量结果以生成后的受管图结构为准，同时保留原 XML 的扩展属性、监听器、未知流程元素、自定义开始/结束节点 ID 和已有 BPMNDI 坐标；显式删除的节点和连线不会被恢复。
- 流程审批角色在生成后再次查询后端权威目录校验；查询失败与不存在的角色都拒绝返回可应用结果。分类编码允许编辑，仅按 `categoryId` 排除自身后检查全局冲突，分类名称不附加后端不存在的唯一性规则。
- VForm3 的更新、删除和移动支持嵌套控件；无效操作目标只做一次确定性纠正，仍失败则返回可重试错误，不拼装草稿。
- 回滚历史固定保留打开设计器时的真实基线；删除重叠的 reset 意图。全部重新生成必须由用户显式勾选并确认，返回结果仍经过预览后才应用。
- 所有运行时 Markdown 提示词均登记版本；设计 SSE 禁止代理缓冲，设计与聊天流都支持前端取消请求；聊天 checkpoint 按认证用户隔离，健康接口明确显示结构化模型降级是否具备至少两个可用 Provider。

## 目标

- 所有分类、流程基本信息、BPMN 与 VForm3 设计统一输出增量操作；新建是在空基线上应用操作，重做使用 replace 操作。
- 操作只在副本上执行，语法与业务校验全部通过后返回 `ready`；信息不足返回 `needs_input`，失败返回 `error`。
- 删除向用户返回可应用半成品的逻辑；非 `ready` 结果不得覆盖当前设计。
- 修复 BPMN 分支挤压、错误 waypoint 与导入后未适配视口的问题。
- 单轮和多轮黄金用例统一为会话结构，并把操作、校验、降级与结果写入 Langfuse 链路。

## 实施顺序

1. 定义统一响应状态、流程/表单操作模型和副本应用逻辑。
2. 归一化 BPMN/VForm3 当前基线，隔离会话并重置单轮执行状态。
3. 补齐语法校验、业务引用校验和安全兜底。
4. 使用拓扑分层布局生成 BPMNDI，并在前端导入后适配视口。
5. 前端增加待应用预览、变更清单、应用/放弃和选择项交互。
6. 重构黄金集为单轮/多轮会话并补充 Langfuse 评分。
7. 完成 AI、前端与 Java 侧验证，review 后提交。

## 已确认的测试 seam

- AI 设计响应：`ready / needs_input / error`。
- 增量操作：在基线副本上应用，原对象不被修改。
- 编译校验：BPMN/VForm3 产物满足语法与业务约束。
- 前端应用：只有用户确认 `ready` 结果后才更新正式设计。

## 关键安全约束

- 查询失败不等于查询结果为空。
- 只允许自动修复 ID、格式、默认配置和布局等不改变业务语义的问题。
- 任何失败都保留原流程和原表单；失败候选仅进入日志与 Langfuse，不返回为可应用结果。
