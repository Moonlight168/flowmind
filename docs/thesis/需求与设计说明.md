# FlowMind 需求与设计说明

## 1. 角色与业务边界

| 角色 | 主要操作 | 必须验证的边界 |
| --- | --- | --- |
| 流程管理员 | 分类、模型、表单、发布 | 菜单权限与接口权限，发布前模型校验 |
| 申请人 | 填表、存草稿、提交、查看自己的流程 | 草稿归属，实例取消与删除权限 |
| 审批人/候选人 | 签收、通过、退回、拒绝、委派 | 当前任务归属、候选资格、实例一致性 |
| 抄送接收人 | 查看被抄送流程 | 只读访问，不自动获得审批权 |
| AI 设计使用者 | 描述需求、检查预览、确认应用 | 会话归属、生成与保存分离、真实引用 |

## 3. 部署与数据流

开发浏览器经 `18088` 的 Nginx 获取 Vite 页面，`/dev-api/` 转发 Gateway；Gateway 负责业务入口认证。AI 服务在容器内部使用 `8000`，前端和 webhook 代理分开。

Langfuse Remote Experiment 预期访问 `http://flowmind-webhook/webhooks/experiment`：Docker 内部 Nginx 监听标准 HTTP 80，再转发 AI 的 8000。此代理不发布宿主机端口。FlowMind 的独立 Langfuse 栈通过共享 FlowMind 网络访问该服务，Web 界面默认使用 `13001`。

AI 业务链路：需求与当前设计 → 检索真实业务数据 → 结构化操作 → 基线副本应用与校验 → 预览 → 用户确认 → 回填设计器。回填不等于保存，保存不等于部署，部署不等于发起实例。

## 4. 核心数据关系

- 分类组织流程模型；模型版本发布后形成流程定义。
- 流程定义实例化为运行实例，实例产生任务及历史记录。
- 表单定义提供字段结构；申请和审批提交的数据通过相应流程变量保存。
- 草稿属于具体用户，不能仅凭草稿 ID 读取或覆盖。
- AI 会话和前端版本缓存按用户隔离；Langfuse trace 用于追踪一次执行，不是业务主数据。

数据库表名、字段类型和约束以仓库 SQL、实体及 Mapper 为准。最终 ER 图应逐项核对源码；需要查询实际数据库时使用项目规定的 DBX，不把数据库密码写进论文。

## 5. 安全与异常设计

审批提交禁止覆盖 `initiator`、`processStatus`、跳过表达式开关及多实例计数等系统变量。退回节点查询与任务办理共用权限边界。

下一审批人只作用于当前完成动作产生的新任务。标准并行会签按目标人员调整，删减执行不算审批通过；多个下一节点存在歧义、串行会签或自定义分配表达式不能安全处理时拒绝临时改派，事务回滚。

Langfuse 可观测失败与业务失败分别记录；webhook 的 HTTP 202 仅说明请求已接收，后台仍可能因令牌缺失、数据集不存在、模型不可用而失败。

## 6. 范围限制

本说明不将未实现功能列为已实现。AI 可生成配置的范围与限制见 [AI 设计支持清单](../AI_DESIGN_SUPPORT.md)。性能、业务正确率和多用户稳定性必须通过专门实验取得数据，不能由单元测试数量推导。
