# FlowMind 部署与用户手册

## 1. 环境与安全准备

使用 Docker Desktop/Compose、Git；本地编译需要与各子项目配置相符的 JDK/Maven、Node.js 与 Python/Poetry。具体版本以仓库构建文件和锁文件为准。

准备仓库规定的环境文件，分别配置数据库、模型提供商、Langfuse 和专用测试账号令牌。不要把 `.env`、浏览器登录态或真实业务数据作为毕业设计附件提交。

开发与生产使用同一 Web 端口，不要同时启动。启动前检查 `docker compose ls` 和当前容器状态，避免误操作同机的其他项目。

## 2. 开发环境

在仓库根目录进入编排目录：

```powershell
cd docker/flowmind
docker compose -f docker-compose.yml config --quiet
docker compose -f docker-compose.langfuse.yml config --quiet
docker compose -f docker-compose.yml up -d
docker compose -f docker-compose.langfuse.yml up -d
docker compose -f docker-compose.yml ps
docker compose -f docker-compose.langfuse.yml ps
```

首次运行可能需要拉取镜像、准备 Java JAR 或构建应用镜像；仅执行 `restart` 不会应用 Compose 环境变量或端口变化，`up -d` 会按配置重建必要容器。Java 源码改动后需重新打包并构建相应镜像；前端与 AI 的开发源码挂载支持热更新，但不能代替依赖更新和镜像重建。

| 用途 | 默认入口 |
| --- | --- |
| OA 与后台 Web | `http://localhost:18088` |
| FlowMind 独立 Langfuse | `http://localhost:13001` |
| Nacos 控制台 | `http://localhost:19090/nacos` |
| AI 内部就绪探测 | `http://flowmind-ai-service:8000/health/ready`，容器内访问 |
| Langfuse 实验 webhook | `http://flowmind-webhook/webhooks/experiment`，共享 Docker 网络内访问 |

Langfuse 的初始化变量不代表能覆盖已有数据卷中的项目或 API key；连接验证必须使用目标实例里实际存在的项目密钥。

## 3. Langfuse 验收步骤

1. 检查 AI 的实际目标地址是否是 FlowMind 独立实例，不能误指向另一项目的 `3000`。
2. 使用运行环境中的密钥访问公开 API，只记录状态码与项目名，不打印认证头。
3. 写入一条明确标注为部署冒烟的 trace，并在 API/UI 中查回，证明不只是密钥格式正确。
4. webhook 从 Langfuse 所在网络访问内部 80 代理；检查代理到 AI 8000 的转发。
5. 配置有效的专用测试账号令牌，确认对应数据集已上传，先触发单条用例。
6. 检查后台日志、Dataset Run 和用例结果。HTTP 202 不代表实验成功，trace 存在也不代表模型业务结果正确。

不要为方便测试而把内部 webhook 发布到宿主机 80 或放开前端公开入口。

## 4. 用户操作

### 流程管理员

创建分类 → 填写模型基本信息 → 创建/选择表单 → 设计 BPMN → 检查审批人、条件与表单引用 → 保存 → 部署。AI 生成只提供候选结果，先阅读变更预览，再决定应用；应用后仍可手动编辑。

### 申请人

在 OA 工作台选择已发布流程，填写申请表单。未完成必填项时可保存申请草稿，正式提交时仍需通过校验。提交后从“我的流程”查看状态与流转记录。

### 审批人

在“待签收”认领候选任务，在“待办事项”查看表单、意见和历史。根据业务处理通过、退回、拒绝、委派或转办。指定下一审批人不等于任意更改所有并行任务；不支持安全临时改派的多实例配置需回到模型调整。

### 数量提示

角标只提示待处理工作，零不显示，超过 99 显示 `99+`。待签收包含在待办总量内，不重复累加；抄送历史总数不当作未读消息。列表长内容可悬浮查看，窄屏通过表格内横向滚动查看全部列。

## 5. 常见问题

| 现象 | 检查方向 |
| --- | --- |
| `no configuration file provided` | 当前目录或 `-f` 路径错误 |
| `No such image` | 先拉取编排指定镜像，不擅自换成不兼容版本 |
| Web 入口无响应 | Nginx、Vite、端口占用和内部服务名解析 |
| Langfuse 401 | 实例与项目密钥不匹配，不能靠重启修复 |
| webhook 202 但无实验 | 后台日志、`FLOWMIND_AUTH_TOKEN`、数据集名称、模型及网络 |
| Java 修改没有生效 | 检查 JAR、Docker 构建上下文和镜像时间，而非只看容器重启时间 |

禁止用 `down -v` 或清空数据库作为一般故障排查步骤。需要数据库核验时使用 DBX；生产数据迁移应单独备份、审批和验证。
